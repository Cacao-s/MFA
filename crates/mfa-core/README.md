# mfa-core

The platform-independent core: everything the app does that is not drawing or
talking to an OS.

Nothing here performs I/O, reads a clock or touches the network. Time arrives
as seconds or milliseconds since the Unix epoch, and files arrive as byte
slices. That is what makes the RFC vectors and the merge rule testable on Linux
CI, and what keeps behaviour identical on all four platforms.

## What is here

| Module | Responsibility |
|---|---|
| `totp` | RFC 4226 dynamic truncation over SHA1/SHA256/SHA512, 6-8 digits, and the countdown arithmetic the list UI needs |
| `secret` | The shared secret: wiped on drop, redacted in `Debug`, compared in constant time, Base32 on the wire |
| `uri` | `otpauth://` parsing and generation |
| `migration` | `otpauth-migration://` imports, including multi-QR exports |
| `protobuf` | The sliver of protobuf `migration` needs, so `protoc` stays out of four platform builds |
| `vault` | The account document, its tombstones, and its merge rule |
| `crypto` | XChaCha20-Poly1305 and Argon2id |
| `container` | The file envelope shared by the vault, backup and sync files |
| `backup` | Password-protected export and import |
| `sync` | Read-merge-write against a file in the user's own cloud folder |
| `pin` | The app lock's PIN fallback |
| `qr` | Decoding a QR code from an image or screen grab (feature `qr-image`) |
| `platform` | The traits each platform shell must implement — and the step-0 spike must prove |

## Decisions worth knowing before reading the code

**The vault is mergeable from v1.** Every entry carries a UUID, a modification
time and a tombstone flag, and `Vault::merge` is commutative and idempotent:
`merge(a, b)` and `merge(b, a)` produce byte-identical documents, and merging
twice changes nothing. Later modification wins; an exact tie goes to the
tombstone, because resurrecting a deleted account is worse than losing an edit.
`tests/merge.rs` pins all of this down, including three devices merging in
different orders.

**The vault keeps one canonical order.** `entries` is sorted by id, so a
document that has been through a save, a backup or a merge compares equal to
the one it came from, and two devices holding the same accounts write
byte-identical files. Display order is separate: see `Vault::visible`.

**File headers are authenticated.** The magic, the format version and the
recorded Argon2id cost are all part of the AEAD's associated data. A vault file
cannot be passed off as a backup, and an attacker who can edit the file cannot
talk a client into deriving the key with cheap parameters and then brute-force
the password offline. `tests/backup.rs` proves the cost cannot be weakened.

**Sync needs its own key.** The local vault's data key lives in the device's
secure store and never leaves it, so it cannot be the key for a file other
devices read. A sync set therefore has a random sync key of its own, published
once in a key file wrapped with the user's sync password; after that an
ordinary sync costs no key derivation. See the module docs in `sync.rs`.

**Import never half-applies.** `backup::import_into` decrypts and parses the
whole file before touching the target vault, so a wrong password or a truncated
file leaves existing data exactly as it was — a spec §5 requirement that is
easier to make true by construction than by care.

**Fixtures come from elsewhere.** The migration payloads and the expected TOTP
codes are generated by independent Python scripts in `../../tools/`, written
from the published specifications. A fixture produced by the code under test
proves nothing.

## Features

- `qr-image` — decode a QR code out of a PNG or JPEG (desktop "add from image
  or screen grab"). Off by default so mobile builds do not carry an image
  decoder they have no use for.

## Tests

The test files are organised as the acceptance criteria, not as the modules:

```
tests/rfc6238.rs      RFC 6238 Appendix B, all three hashes  (spec §5)
tests/otpauth_uri.rs  parsing what issuers really emit
tests/migration.rs    Google Authenticator imports           (spec §5)
tests/vault.rs        editing, searching, sealing, refusals
tests/merge.rs        convergence                            (spec §3)
tests/backup.rs       export, import, wrong password         (spec §5)
tests/sync.rs         two and three devices converging        (spec §3)
tests/qr_image.rs     image decoding                         (spec §1)
```

```sh
make test     # from the repository root
```
